从登记到分发，再到冲突检查，都在同一套索引上。

扫描

读取每个 SKILL.md 的名称、分类、备注和内容哈希，建立本地索引。

分发

在 Agent 目录建立 junction；失败才复制。一个开关只动链接。

校验

verify 报告缺失、漂移和同名冲突，不静默合并，也不改动磁盘。

整理

SkillLocker CLI 命令
命令作用

status打印分发矩阵摘要：共有、独有、冲突。
verify检查漂移与冲突，只报告，不改动磁盘。
sync [--tool] [--fix]建立或修复分发；不带 --fix 时先报告。

search <keyword>在 skills.sh 检索，先看再取。
fetch <owner/repo/skill>把远端 Skill 取到临时目录。

把担心先写清楚。

本地优先，链接优先，冲突先报告。下面是几个最常见的问题。

数据会离开本机吗？

技能库、索引和分发都在本地。只有 search 和 fetch 会访问网络；scan、status、verify、sync 不联网。

它会把 Skill 复制到每个 Agent 吗？

优先 junction。junction 失败时才回退到复制；复制也会记录内容和哈希。

同名但内容不同怎么办？

标为冲突。verify 只报告，不自动覆盖；你可以查看差异，再决定保留哪一份。

删除一个 Skill 会删掉 Agent 里的东西吗？

不会顺着链接递归删实体。撤链和删实体分开；删除前先判断 reparse point。

需要账号或后台服务吗？

不需要。桌面端是 pywebview，后端与 CLI 无第三方依赖，数据落在本地 SQLite 与文件系统。

装好，打开就用。
